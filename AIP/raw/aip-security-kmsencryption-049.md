# aip-security-kmsencryption-049: KMS 与静态、传输中加密边界

日期：2026-10-21
范围：Node.js 通过 HTTPS 上传和下载 S3 对象
来源：本次学习对话整理；原始 KP 来源见 References

## 1. 先区分两种保护场景

| 场景 | 名称 | 本例使用的机制 |
|---|---|---|
| 数据通过网络传输 | Encryption in transit，传输中加密 | HTTPS/TLS |
| 数据保存在存储中 | Encryption at rest，静态加密 | S3 SSE-KMS |

“静态”指数据处于存储状态，不代表文件不能修改。

两者分别保护不同阶段。对象使用 SSE-KMS，不代表上传和下载就自动具备传输保护。

## 2. HTTPS 与 TLS 的关系

HTTPS 是通过 TLS 保护的 HTTP 通信。

- HTTP：定义请求和响应。
- TLS：提供传输加密、完整性保护和身份验证。
- HTTPS：把两者组合起来。

因此，“使用 HTTPS 上传文件”已经包含使用 TLS，不需要额外再套一层 TLS。

### 证书与会话密钥分别做什么？

- 证书：帮助客户端验证服务器身份，例如证书是否可信、是否过期、域名是否匹配。
- 会话密钥：用于加密实际传输的数据。

证书不是“把域名加密”，也不是直接用来加密整个文件。

本次语音讲解中曾出现“HTTP 负责加密和完整性”的口误；正确的是 TLS 负责这些保护。

## 3. HTTPS 上传的简化过程

以 Node.js 上传文件到 S3 为例：

1. DNS 将 S3 域名解析为 IP。
2. 客户端与服务器进行 TLS 握手。
3. 客户端验证服务器证书，双方完成密钥协商。
4. TLS 使用协商出的流量密钥保护 HTTP 请求和文件内容。
5. S3 的 TLS 端接收并解密传输数据。
6. S3 按配置执行静态加密，再保存对象。

这是概念流程；证书验证和密钥建立属于握手过程，不是完全独立的两个阶段。

在本例中，TLS 流量密钥不由 S3 的 SSE-KMS 配置提供。

## 4. SSE-KMS：两层密钥

SSE-KMS 使用信封加密：

- 数据密钥（Data key）：加密和解密对象内容。
- KMS 密钥（KMS key）：保护数据密钥。

记忆方式：

> 数据密钥锁文件，KMS 密钥锁数据密钥。

### 谁保存什么？

| 位置 | 保存或使用的内容 |
|---|---|
| KMS | 管理 KMS 密钥及其使用权限 |
| S3 持久存储 | 密文对象、加密后的数据密钥 |
| S3 处理期间 | 临时使用明文数据密钥，用完后清除 |

“明文数据密钥”是尚未被加密包装的密钥，不是指文件内容。

S3 不会把明文数据密钥长期保存到对象旁边。

## 5. 上传并保存：SSE-KMS 的基本流程

以下为不展开 S3 Bucket Key 优化的基本模型。

1. Node.js 通过 HTTPS 将文件传到 S3。
2. S3 向 KMS 请求生成数据密钥。
3. KMS 返回同一把数据密钥的两种形式：
   - 明文数据密钥；
   - 被指定 KMS 密钥加密后的数据密钥。
4. S3 使用明文数据密钥加密对象。
5. S3 保存密文对象及加密后的数据密钥。
6. S3 清除临时使用的明文数据密钥。

KMS 密钥本身不会随对象保存到 S3。

## 6. 下载：“出库”的基本流程

1. Node.js 通过 HTTPS 请求下载对象。
2. 请求需要具备相应的 S3 读取权限，以及适用的 KMS 解密权限。
3. S3 读取密文对象及加密后的数据密钥。
4. S3 请求 KMS 解开加密后的数据密钥。
5. KMS 使用 KMS 密钥，恢复明文数据密钥并返回给 S3。
6. S3 使用明文数据密钥解密对象内容。
7. S3 通过 HTTPS/TLS 将内容传回 Node.js。
8. Node.js 的 TLS 层解密网络数据，应用拿到原始文件内容。
9. S3 清除临时使用的明文数据密钥。

这是职责上的拆解，不要求完整文件解密结束后才开始传输。

记忆方式：

> KMS 解钥匙，S3 解文件，TLS 保护传回来的路。

## 7. 为什么同一把数据密钥可以加密和解密？

本例中的对象内容采用对称加密。

保存时使用数据密钥加密，读取时使用同一把数据密钥解密。

加密后的数据密钥只是这把钥匙被保护起来的形式；读取时先恢复钥匙，再解开对象。

## 8. 本次理解与纠正

### 已在对话中表达的理解

- Node.js 通过 HTTPS 上传文件时，TLS 负责传输保护。
- S3 保存密文对象和加密后的数据密钥。
- 明文数据密钥用于解开加密后的对象。
- 下载涉及存储解密和传输保护两个阶段。

### 本次纠正的混淆

1. HTTPS 不是“域名加密”；证书验证身份，TLS 保护通信内容。
2. HTTPS 是 HTTP 与 TLS 的组合。
3. S3 不长期保存明文数据密钥。
4. KMS 密钥保护数据密钥，数据密钥保护对象。
5. SSE-KMS 不替代 HTTPS/TLS。
6. “上传和下载如何保护传输安全”那道题应选 B。
   当时口头选了 A，但解释中已提到下载需要 TLS；选项与理由不一致。

## 9. 考试速记

- 网络传输保护：HTTPS/TLS。
- S3 对象使用 KMS 管理密钥进行静态加密：SSE-KMS。
- 证书：验证身份。
- TLS 流量密钥：保护网络通信。
- 数据密钥：加密和解密对象。
- KMS 密钥：保护数据密钥。

> 传输看 TLS，落盘看静态加密，密钥管理看 KMS。
